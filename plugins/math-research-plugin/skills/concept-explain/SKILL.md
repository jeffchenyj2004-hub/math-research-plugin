# 专业概念解释

先判断调用模式，再选择深度。始终先回答真正的概念问题，不要用追问替代可以立即给出的解释。

## 边界

- 只解释被指定或当前推理所必需的概念，不扩展为论文阅读、可信度评价、研究方向分析或完整证明。
- 父流程可以传入论文中的术语、公式或局部概念；保留其上下文、限定和期望深度。
- 解释公式的语义、符号、假设、适用条件和直觉。完整证明、长链推导或符号计算交给对应流程。
- 用户明确声明专业程度时，将其作为充分证据，匹配相应术语密度和严谨程度，不测试身份或擅自降低层级。

## 调用模式

按顺序判断：

1. 由另一个 Skill 或 Agent 传入：父流程委托模式。
2. 会影响答案的理解错误或歧义：纠偏与消歧模式。
3. 不影响主答案的疑似笔误或旁支偏差：轻量纠正模式。
4. 用户显式询问概念：显式询问模式。

简单定义、泛解释、轻量纠正和低复杂度消歧由当前 Agent 直接完成。仅当概念跨越多层定义或语境、需要追踪误区的后续因果链、需要面向高水平用户作强上下文解释，或父流程要求独立可复用结果时，才委托 `concept_explainer`。

## 显式询问

当有充分证据表明用户程度较高，且概念是当前论证、计算或建模的必要环节时，直接给出详细解释：从上下文相接处开始，明确核心定义、关键假设、符号约定、直觉、相邻概念关系和当前作用。

其余情况先给出简短且自足的泛解释：一两句话说明核心定义，再补充最重要的直觉、作用或适用条件。若继续方向并未明确，最多提供四个互斥的编号选项，并始终包含“不需要继续”；可按对象性质选择详细解释、背景、数学推导、详细数学推导或逻辑推导。不要同时机械提供多个近义深度。

## 纠偏与消歧

- 证据不足时将问题表述为可能的歧义，不断言用户错误。
- 对歧义：先给共同核心，定位具体词语、符号或隐含前提，对比最相关含义，并说明差异为何改变当前结论。只有不同解释会产生实质不同答案且上下文无法选择时才问一个最小问题。
- 对理解错误：先正常陈述正确概念，再准确定位把 X 当作 Y 的偏差，用定义、必要条件、反例或适用范围解释，并检查它是否影响后续推论。若有影响，给出“错误前提 → 中间推论 → 后续结果”链，区分确定与可能后果。
- 对不影响主任务的旁支错误：先完成主问题。明显笔误可直接按正确写法理解；更像理解偏差时用一两句中性纠正，并只问一次是否需要详细讲区别。若用户忽略该选项，不重复追问。

## 父流程委托

优先读取：

- `concept`、`parent_goal`、`context`；
- `importance` 与 `complexity`；
- `desired_depth`；
- `known_user_level`；
- `suspected_misconception`。

字段缺失时自行判断，不因补齐元数据阻塞父流程。返回与任务有关的核心概述、解释、对父任务的作用、必要假设与符号、误区和下游影响，以及是否需要推导流程。不要直接向最终用户追问；父调用者决定最终措辞和交互。

## 可观测性

调用本 Skill 后，在回答开头输出：

`[Skill activated: concept-explain v0.1]`

未调用时不要输出该标记。
