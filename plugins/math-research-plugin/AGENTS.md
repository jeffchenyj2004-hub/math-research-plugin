# 数学科研 Plugin 协作规则

## 命名与运行边界

- Agent 名使用表示执行者的英文词并以 `-er` 结尾；Skill 名使用动作或能力名称，不使用该结尾。
- 本 Plugin 自动分发 Skills。`agents/*.toml` 是自定义 Agent 的可分发权威模板，项目根 `.codex/agents/*.toml` 是内容完全一致的运行副本；当前 Codex 只从项目根自动发现这些 Agent，安装 Plugin 不会单独注册它们。映射见 `references/agent-catalog.md`。
- `logical-reasoner`、`formula-deriver` 和未来的 `task-intent-clarify` 仍属计划组件；本阶段只有前两个的只读占位 Agent，绝无反问 Skill 文件。

## 论文意图路由

`paper-intent-route` 是尚未分类论文请求的唯一宽入口。它可在顶层请求涉及论文来源、论文阅读、引用写作、文献学习、比较或审查时隐式触发，也可由顶层协调者显式调用；每个顶层用户回合最多运行一次。任何下游 Skill 或 Agent 均不得回调它。

路由契约仅供内部协调。除 `clarify` 和未实现的 `audit` 降级外，顶层协调者须在同一回合立即调用选定下游并向用户交付实际结果；普通模式不得把 YAML 契约作为最终答复。

判定优先级：当前回合明确要求 → 已建立的对话任务 → 写作、学习、综述、项目、比较或审计线索 → 论文与上下文的相关程度 → 项目根 `AGENTS.md` 中的长期偏好。

- 包含 PDF、题名、DOI、arXiv 或网址时，先用 `paper-source-resolve` 建立证据层级明确的来源卡。
- 当前核心论文走 `paper-detailed-explainer`；旁支论文走 `paper-brief-summary`。
- 写作与补引用走 `writing-literature-indexer`；学习、综述与项目调研走 `learning-literature-indexer`。
- 比较对象给齐时直接做 `paper-relationship-analysis`；否则依次执行筛选、检索、关系分析。
- 论文新近且是当前核心，或用户明确要求质疑、复核、验证或可信度审查时，进入 `audit`；新近但只是旁支仍做简明解读。
- 与上下文无关的论文先按用户要求和既有任务归入现有路线；只有两条以上成本差异明显的合理路线并存时才 `clarify`。
- “综述”指文献梳理、学习路径或项目调研时走学习索引；指结论复核、验证或可信度审查时走 `audit`；无法区分且成本差明显时才澄清。
- `audit` 与 `clarify` 对应正式模块尚未实现。必须明确能力边界；审计降级提供编号选项“仅做详细解读与局限梳理”或“等待审计模块”，不能假装已完成审计或调用了不存在的 Skill。

## 来源与解读边界

- `paper-source-resolve` 只确认身份、元数据、访问状态和可用内容层级，不总结论文结论。
- `paper-brief-summary` 只使用摘要和少量目标段落，不阅读全文、不做多轮检索。
- `paper-detailed-explainer` 只处理当前核心单篇论文，不默认做可信度审计；需要概念或推导子任务时按需调用相应 Agent，独立任务可以并行。
- 全文不可用时必须标明证据边界，并让父流程提供“上传全文”或“接受局部分析”的编号选项。
